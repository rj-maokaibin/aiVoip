# 多模态现场验证清单

日期：2026-08-16  
环境：现有开发环境，不部署生产。

## 已自动验证

- Opus/OGG 经 FFmpeg 解码并进入 `field_audio_intelligence`。
- 中英文 Tesseract 可从渲染设备截图提取 `Codec: G711A`，结构化为 L4 候选。
- 敏感关键词行在持久化前替换为 `REDACTED_SENSITIVE_LINE`。
- 录音与媒体 WAV 的确定性相关可输出偏移、绝对抓包时间和 Call-ID。
- 不可靠相关不生成对齐结论。
- 新附件不会被上一份 AnalyzerRun 错误视为已分析。
- Worker 可完成 Job、AnalyzerRun、结果对象存储，并由 Snapshot/Reasoner 消费。

开发回归基线见 `golden_cases/multimodal_field_v1.json`。该文件明确标记为
`SYNTHETIC_DEVELOPMENT_BASELINE`，不能替代真实现场 Golden。

## 需要人工提供的真实输入

1. 在真实飞书群聊发送一条原生语音，记录 `message_id`、Evidence ID、AnalyzerRun ID 和回复。
2. 在机器人私聊发送一张真实设备状态截图，核对 OCR 原文、脱敏和设备实际页面。
3. 在同一 Case 上传一份 PCAP 和对应手机录音，核对 Call-ID、方向和异常时间。
4. 上传一份与 PCAP 无关的录音，确认结果为 `NO_RELIABLE_MATCH`。
5. 提供至少一组修复前/修复后附件，跑完 FixVerification。

## 通过标准

- 飞书资源下载、Evidence 登记、Job、AnalyzerRun、诊断恢复和原线程回复全部可追溯。
- OCR 不保存密码、Token、Secret 原文；OCR 候选不升级为确定性事实。
- 对齐仅在 MEDIUM/HIGH 时展示，错误 Call-ID 映射数必须为 0。
- 对齐成功后不得再显示“尚未对齐”；不匹配时不得声称来自同一通话。
- 真实样本完成前，产品继续标记为开发验证状态。
