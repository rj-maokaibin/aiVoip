# 真机话机验证测试用例（2026-08-15）

> 需要客户现场配合人员在话机旁执行的可靠性/稳定性/准确性验证。
> 设备：APF3260-M（MACC1JZH3260M），隧道 `47.104.22.0:65212`。
> 前置：单聊/群聊发 `打开SSH sn=MACC1JZH3260M ip=47.104.22.0 port=65212` 触发复现，
> 等约 30s watcher 启动后再话机操作。

**通用验证流程**：每次用例 = 触发复现（飞书消息）→ 话机按步骤操作 → 我侧检查
（CALL findings / PCM 捕获 / 段落库 / 诊断 / 卡片）。

---

## P0 基础可靠性（必做基线）

| # | 用例 | 话机操作 | 预期 | 我侧验证点 |
|---|---|---|---|---|
| P0-1 | 标准单次通话 | 摘机→拨号(10086)→通话 3~5s→挂机 | 完整捕获、CALL 分析、诊断、卡片回推 | findings、pcap 非空、卡片 msg_id |
| P0-2 | 极短通话 | 摘机→立即挂机(<1s) | 不产生空 pcap，优雅处理 | 无 CALL_CAPTURE_SEGMENTS_MISSING |
| P0-3 | 长时间通话 | 摘机→拨号→通话 **60s+**→挂机 | 通话全程 PCM 持续捕获 | 通话中段 LIVE_PROBE 段落库（on_segment）|
| P0-4 | 不拨号通话 | 摘机→等回铃→挂机（不按号码） | 无 DTMF，但 PCM 捕获正常 | findings 无 DTMF，pcm_session=2 |

## P1 多次操作（现场人员场景）

| # | 用例 | 话机操作 | 预期 | 我侧验证点 |
|---|---|---|---|---|
| P1-1 | 连续 2~3 次完整通话 | 摘→拨→通→挂，重复 2~3 次 | 每轮独立 call 捕获分析，不串扰 | call 数量 = 轮次，每 call 有 pcap |
| P1-2 | 快速连续摘挂 | 摘→挂→立即摘→挂（<1s） | 状态机稳定，无卡死 | 多次 attempt，均 INVALID，回 WATCHING |
| P1-3 | 多次拨号后挂机 | 摘机→按 3 个不同号码→挂机 | 所有 DTMF 记录 | FXS_DTMF 事件数正确 |
| P1-4 | 通话中多次按键 | 摘→拨→通→**通话中按 123#**→挂 | 通话中 DTMF 落在捕获窗，检出 | findings 含 DTMF_PATH（或静音特征）|

| # | 用例 | 验证点 |
|---|---|---|

## 建议执行顺序（兼顾可行性与信息量）

1. **P0-1 + P3-1 + P4-1/2/3**：标准通话一次 → 覆盖基础可靠性 + 捕获完整性 + 负控制（**最高价值，必做**）
2. **P1-1**：连续 3 次通话 → 多次 call 不串扰
3. **P1-4 + P3-2**：通话中按键 → DTMF 检出 → DIAGNOSED + 卡片（已验证，再确认）
4. **P0-3**：长通话 60s → 通话全程捕获持久化
5. **P2-1/P2-2**：回声 / 快速拨号 → 真实故障检出（可行的话）
6. **P0-2、P1-2**：极短通话、快速摘挂 → 边界容错

> 每次用例前都会重新触发一次复现（新 session），避免跨用例数据串扰。
