## 执行前置检查清单（每轮开始前）

1. 隧道：`tools/dev_tunnel_check.py` → `TUNNEL_OK`（设备重启会导致隧道失效，需人工重开 + 告知新端口）。
2. 平台：`REPRODUCTION_PLATFORM_MODE=real`，且 Cleanup metadata 预期 `mock_platform=false`。
3. Session：每个用例使用**独立 Session**，确认进入 `WATCHING` 且 Ring producer 正常后再操作话机。
4. 前置状态：无残留 `WATCHING/CAPTURING/ARMING` Session、无未释放 DeviceDiagnosticLock。

## 每轮统一四维检查

- **动作**：OFFHOOK、DTMF、SIP、RTP、ONHOOK 是否完整且顺序正确。
- **采集**：PCM 双向、PCAP 连续、Segment 无空洞伪影。
- **诊断**：路径存在 ≠ 故障；正常通话不得出现错误 `SUPPORTED` 结论。
- **安全**：Cleanup、Manifest、锁和 DUT producer 全部收口。

## 自动重算工具

`tools/dev_case_ledger.py` 从复现 DB 重算本台账的状态，避免手工对账：

```bash
# 报告（含跨切面事实与逐 ID 判定）
PYTHONPATH=backend python tools/dev_case_ledger.py

# 执行一轮后把 session 绑定到用例，再重算
PYTHONPATH=backend python tools/dev_case_ledger.py --label <session_id>=RP-R01

# 输出机器可读结果
PYTHONPATH=backend python tools/dev_case_ledger.py --json validation/rp_case_ledger.json
```

设计约束：DB 不记录操作意图（"说话5秒静音5秒"与"通话30秒"在 schema 中无法区分），
因此工具**不做启发式猜测**：

- Session 只通过显式标注（`docs/真机用例执行台账.labels.json`）绑定到 RP 用例；
  已标注的 Session 按该用例的声明判据自动判定。
- 未标注 Session 仍贡献**跨切面事实**（已采集过哪些 DTMF 数字、是否存在 in-call DTMF
  事件、残留 ACTIVE 行数、锁状态）——这些是矩阵级缺口，不是单例结论。
- 既无标注又无跨切面证据的用例保持 `NOT_RUN`，工具不会凭旁证把用例升级为 PASS。
- `PASS*`（`PASS_NEEDS_NOTE`）表示自动判据全过，但该用例编码了 schema 无法确认的
  操作意图，接受前须补操作者说明。

无论用例声明了什么，安全维度（cleanup=VERIFIED、`mock_platform=false`、
Manifest+checksum、无残留 ACTIVE attempt）对所有已标注 Session 一律强制。
