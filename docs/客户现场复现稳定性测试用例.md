# 客户现场复现稳定性测试用例（2026-08-15）

> 目标：真实客户现场环境下，保证"SSH 远程诊断复现"的**采集稳定性**（采集是基石）。
> 本用例基于确认的现场模型设计，覆盖人工操作、隧道生命周期、多型号、网络/并发等不可控因素。

## 确认的现场环境模型

| 维度 | 确认结果 | 影响 |
|---|---|---|
| 网络 | 设备?服务器通过 **EWEB SSH 隧道**，**人工开启 + 告知**端点 | 隧道是人工依赖项 |
| 凭据 | SSH 密码**固定不变**；隧道 stok/stamp/pass 约 **3h 过期** | 只需关心隧道过期 |
| 话机 | **客户现场配合人员手动操作**（不专业） | 操作容错 + 清晰指引 |
| 型号 | **APF 系列**（多型号，命令/固件有差异） | 型号适配/兼容 |
| 网络条件 | 不确定 → 保守（按受限/抖动设计） | 大 pcap 回传分块/重试 |
| 并发 | 不确定 → 保守（按多设备设计） | 锁隔离 + 资源保护 |

---

## P0：隧道生命周期（最核心，人工开启 + 3h 过期）

| # | 场景 | 前置 | 步骤 | 预期 |
|---|---|---|---|---|
| P0-1 | 有效期内复现正常 | 新开隧道 + 告知端点（已写入 DB） | 单聊发消息 → 话机操作 | 全流程正常，证据落库 |
| P0-2 | **隧道过期后复现** | stok/pass 3h 过期 | 旧端点复现 | **明确提示"隧道过期需人工重开+告知"**，不静默失败 |
| P0-3 | 复现中隧道断开 | 有效期内 | watcher 运行中断连 | 自动重连重试（任务 autoretry）或标记人工 |
| P0-4 | **人工重开后恢复** | 重开新隧道 | 告知新端点 → provision 原子更新 DB → 复现 | DB 端点更新 + 复现成功 |
| P0-5 | 旧端点误导 | DB 旧端点，实际已换新 | 直接复现 | 连接失败快速识别 + 明确提示，不无限重试 |

**验收工具**：`tools/dev_tunnel_check.py`（输出 TUNNEL_OK / UNREACHABLE / AUTH_FAILED / CMD_FAILED + 人工动作指引）。

## P1：现场配合人员手动操作（不专业）

| # | 场景 | 步骤 | 预期 |
|---|---|---|---|
| P1-1 | 未摘机就拨号 / 乱序操作 | 乱序摘机/拨号/挂机 | 状态机容错，不崩溃 |
| P1-2 | 极短通话（<2s） | 摘机→立即挂机 | final 捕获兜底（补偿），无空 pcap |
| P1-3 | 无人操作超时（15min） | watcher 空转无事件 | 优雅结束 + 自动诊断兜底 |
| P1-4 | 现场误操作（重启设备/断网） | 复现中重启设备 | 重连恢复 + 锁释放（watchdog） |
| P1-5 | 操作指引清晰度 | 现场人员按卡片/提示操作 | 摘机→拨号→通话→挂机步骤明确 |

## P2：多型号 APF 兼容

| # | 场景 | 步骤 | 预期 |
|---|---|---|---|
| P2-1 | 接口名差异（br-lan_XXX） | 不同型号解析 voice context | 型号适配，采集不失败 |
| P2-2 | AIM/debug 命令差异 | 不同固件 FULL_DEBUG | 兼容或优雅降级 |
| P2-3 | 固件版本差异 | 旧固件命令报错 | 容错不崩溃，日志可定位 |

## P3：凭据（已简化）

| # | 场景 | 预期 |
|---|---|---|
| P3-1 | SSH 密码固定 | 密码层无需轮换处理（已确认固定） |
| P3-2 | 隧道 stok/pass 过期 | 归入 P0-2（人工重开） |

## P4：网络不确定（保守）

| # | 场景 | 预期 |
|---|---|---|
| P4-1 | 窄带回传大 pcap | base64 分块/重试，不超时丢数据 |
| P4-2 | 高延迟命令往返 | 超时兜底 + execute_shell 重试 |

## P5：并发不确定（保守）

| # | 场景 | 预期 |
|---|---|---|
| P5-1 | 多设备并发复现 | 锁隔离、资源不耗尽 |
| P5-2 | 同设备并发（2 session） | D1 锁防堆叠，一个退出 |
