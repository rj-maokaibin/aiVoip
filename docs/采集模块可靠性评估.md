# aiVoip 采集模块可靠性评估报告

> 评估日期：2026-08-19
> 评估对象：复现平台「采集模块」（DUT 事件/媒体捕获 → FXS/PCM 分析 → Call 绑定）
> 数据来源：2026-08-16 至 2026-08-19 真机验证全过程（APF3260 / APF1250 两台 DUT）
> 结论：**采集核心链路可靠性不达标**，存在 1 个系统性缺陷（短通话捕获缺失）+ 1 个强干扰项（隧道过期）

## 三、采集模块可靠性评级

### ? 采集核心链路（DUT → 事件/媒体）— 可靠性 **低**
- **短通话(秒级)是薄弱环节**：SIP/媒体捕获不可靠(A1/A2)，导致大量 INVALID/无绑定
- 长通话(>30s)可靠：APF1250 70s 通话段含完整 5060+10000，绑定成功
- **反复性判定**：A1 在 8-17/8-19 双设备 6+ 次出现 → **系统性缺陷，非偶发**

### ? 事件解析链路（FXS/PCM）— 可靠性 **中**
- 快速按键 FXS 漏报(A4) + PCM 漏尾(A5) → 已用并集缓解，但**无单一源完整**是固有限制
- FXS 监视器重启(A3)仅 APF1250，属设备特定

### ? 状态机/编排 — 可靠性 **中**(已修复大部分)
- B1-B4 均已修复+单测，但 B1(OFFHOOK 拆分)只修了表面，**A1 根因(段捕获)未解**
- 清理/锁/心跳已加固(S 类离线复核全绿)

### ? 环境依赖 — 可靠性 **极低**(阻塞性最高)
- **隧道 3h 过期是最大干扰**(C1)：APF3260 87% 会话因此中止
- worker 时钟(C2)+单并发占用(C3)加剧不稳定

## 四、核心结论与建议

### 最严重：短通话信令/媒体捕获缺失(A1)
- 反复出现、双设备复现，是采集模块**核心可靠性缺陷**
- 环段捕获未覆盖短通话 SIP 交换窗口
- **修复方向**(需设计评审)：
  1. 段捕获对齐短通话：预触发(pretrigger)/更细粒度环段
  2. 短通话备用绑定路径：PCM-DTMF / 媒体流辅助绑定(不依赖 SIP 进段)

### 最干扰：隧道 3h 过期(C1)
- 非代码缺陷，但**严重污染验证可靠性**，难以区分"设备问题 vs 环境问题"
- **建议**：隧道过期自动告警/自动重建，或测试前强制刷新

### 已修复项(A2/A4/A5/B1-B4)可靠
- 单测覆盖 + 长通话真机验证通过，可作为基线

### 验证策略调整建议
- 修复 A1 前，**真机验证以长通话(>30s)为主**
- 短通话场景暂标注"已知限制"，避免误判为设备故障
- 每次测试前确认隧道有效性，减少 C1 干扰
